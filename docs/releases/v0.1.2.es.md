# S42 Agent v0.1.2 — Planificación, revisión Git y credenciales para servidores

[English](https://github.com/stock42/s42-agent/blob/v0.1.2/docs/releases/v0.1.2.md) · **Español**

Esta prerelease incorpora planificación visible, verificación e historial Git
al escritorio estilo QBasic. Las API keys LLM ahora persisten en SQLite, también
en servidores sin llavero del escritorio.

## Funcionalidades destacadas

- Planes persistentes en TODO.md con criterios de aceptación y verificaciones
  previstas. Kanban muestra pendientes, en progreso y terminadas; las tareas
  interrumpidas continúan en su sesión de origen.
- Cambios Git por proyecto, diffs seleccionados e historial de commits. El cierre
  registra archivos y SHA conservando staging ajeno; commit y push siguen las
  instrucciones del proyecto activo.
- Inspección y generación de AGENTS.md con preview editable y aplicación
  explícita. Inicializar Git sigue siendo una acción explícita del proyecto.
- Chrome DevTools MCP opcional conservado por proyecto. Los checks web registran
  pasos, esperado/observado y evidencia real de tools; las capturas y artifacts
  permanecen asociados a la sesión.
- API keys LLM en SQLite nativo, separadas por configuración, proveedor y
  endpoint. TUI y CLI recuperan credenciales sin Bun.secrets, D-Bus ni llavero
  del SO. Se conservan overrides CLI en memoria y alternativa de entorno.
- Diecisiete tools nativas: fetch para HTTP/APIs, scrape para páginas renderizadas,
  búsqueda en el historial y herramientas de planificación/verificación.
- Website bilingüe con doce funcionalidades, diez preguntas frecuentes por
  idioma y capturas reales del Kanban.

## Actualización y almacenamiento de claves

Cerrá el agente y ejecutá nuevamente el instalador Unix o PowerShell. Se conservan
proyectos, configuración e historial. Las claves anteriores del llavero deben
ingresarse una vez en **Models → Proveedores** para guardarlas en SQLite.
Las credenciales se guardan sin cifrado adicional; con configuración JSON legacy
se usa `config.json.credentials.sqlite` junto al archivo. Las claves no se guardan
en JSON de configuración ni eventos de conversación.

Los assets incluyen seis ejecutables (Linux glibc, macOS y Windows en x64/ARM64),
checksums SHA-256, manifiesto, instaladores, licencia MIT y
`s42-agent-0.1.2-all-platforms.tar.gz`. Bun está incluido en el ejecutable;
servidores/modelos LLM, comandos shell y Chrome/MCP opcional son externos.

Consultá la [instalación](https://github.com/stock42/s42-agent/blob/v0.1.2/README.es.md#instalación),
el [manual](https://github.com/stock42/s42-agent/blob/v0.1.2/docs/USAGE.es.md),
los [contratos de tools](https://github.com/stock42/s42-agent/blob/v0.1.2/docs/TOOLS.es.md)
y el [website](https://s42agent.dev/es/).

## Validación y alcance

El workflow ejecuta typecheck y la suite, compila seis destinos, prueba Linux x64
fuera del checkout sin Bun/Node en PATH y valida checksums/paquete antes del
borrador. El smoke prueba credenciales SQLite persistentes, planificación,
edición, shell, MCP y restauración del terminal con fixtures HTTP aislados.

Linux x64 cuenta con evidencia de runtime nativo. macOS, Windows y ARM64 son
cross-builds sin ejecución nativa validada. La aceptación de mouse físico y
arrastre desde el SO sigue pendiente. El manual distingue fixtures de operación
con proveedor o navegador real; la publicación no agrega evidencia a esos escenarios.
