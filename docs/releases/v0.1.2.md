# S42 Agent v0.1.2 — Task planning, Git review and server-ready credentials

**English** · [Español](https://github.com/stock42/s42-agent/blob/v0.1.2/docs/releases/v0.1.2.es.md)

This prerelease brings visible task planning, verification and Git history to
the QBasic-style workspace. LLM API keys now persist in SQLite, including on
servers without a desktop keychain.

## Highlights

- Persistent execution plans in TODO.md with acceptance criteria and planned
  verification. A Kanban board shows pending, in-progress and completed work;
  interrupted tasks can continue in their original session.
- Per-project Git changes, selected diffs and commit history. Task closeout
  records its files and SHA while preserving unrelated staging; commit and push
  behavior follows the active project's instructions.
- AGENTS.md inspection and generation with an editable preview and explicit
  application. Git initialization remains an explicit project action.
- Optional Chrome DevTools MCP connections retained per project. Browser checks
  record steps, expected/observed results and actual tool evidence; captures and
  artifacts remain associated with sessions.
- LLM API keys stored in native SQLite, separated by configuration, provider
  and endpoint. TUI and CLI reuse saved credentials without Bun.secrets, D-Bus
  or an OS keychain. CLI overrides remain in memory and environment variables
  remain available.
- Seventeen native tools, including fetch for HTTP/APIs, scrape for rendered
  pages, session history lookup and the task planning/verification tools.
- Bilingual website with twelve feature highlights, ten FAQ entries per
  language and real Kanban screenshots.

## Update and credential storage

Close the agent and rerun the Unix or PowerShell installer. Existing projects,
configuration and session history are retained. Keys previously saved in the
OS keychain must be entered once in **Models → Providers** to store them in
SQLite. The agent database stores credentials without additional encryption;
legacy JSON configurations use a neighboring `config.json.credentials.sqlite`.
Keys are never written into JSON configuration or conversation events.

Assets contain six executables (Linux glibc, macOS and Windows, each x64/ARM64),
SHA-256 checksums, build manifest, installers, MIT license and
`s42-agent-0.1.2-all-platforms.tar.gz`. Bun is embedded in the executable;
LLM servers, models, shell programs and optional Chrome/MCP remain external.

See the [installation guide](https://github.com/stock42/s42-agent/blob/v0.1.2/README.md#installation),
[user guide](https://github.com/stock42/s42-agent/blob/v0.1.2/docs/USAGE.md),
[tool contracts](https://github.com/stock42/s42-agent/blob/v0.1.2/docs/TOOLS.md)
and [website](https://s42agent.dev/).

## Validation and scope

The release workflow runs typecheck and the source suite, compiles six targets,
executes the Linux x64 binary outside the checkout without Bun/Node in PATH,
and validates checksums and packaging before creating a draft. The binary smoke
exercises persistent SQLite credentials, planning, edit, shell, MCP and terminal
restoration using isolated HTTP fixtures.

Linux x64 has native runtime evidence. macOS, Windows and ARM64 artifacts are
cross-built; native runtime on those platforms remains unverified. Physical
terminal mouse and OS drag/drop acceptance remain pending. Browser/LLM fixture
checks are distinguished from real provider or browser operation in the user
manual; publication does not add evidence to those scenarios.
