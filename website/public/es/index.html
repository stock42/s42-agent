Planificá. Construí. Verificá.

Desde la primera idea hasta un resultado comprobado: funcionalidades para seguir el trabajo de coding y retomarlo cuando lo necesites.

>_

Un escritorio QBasic, vivo.

Menús, atajos, mouse y seis temas. Leé respuestas y salida de tools en vivo, con el prompt siempre a la vista.

[ + ]

Proyectos independientes.

Cada pestaña conserva conversación, modelo, borrador, adjuntos y scroll. Ejecutá trabajo en distintos proyectos y cancelá el turno que elijas.

~/

Tu modelo, a tu elección.

llama.cpp por defecto, DeepSeek u otro proveedor compatible con Chat Completions. Usá modelos locales o conectá un endpoint remoto.

[ ✓ ]

Un plan que podés seguir.

El agente registra etapas y criterios de aceptación en TODO.md. Seguí tareas pendientes, en progreso y terminadas en el tablero Kanban.

git

Cambios que podés revisar.

Inspeccioná archivos, diffs e historial Git desde la TUI. El cierre de tarea selecciona sus archivos y sigue las instrucciones Git del proyecto.

test

Verificación con evidencia.

Conservá juntas las pruebas previstas, los comandos ejecutados, sus salidas y resultados. La tarea terminada y la verificación aprobada tienen registros separados.

↗

Chrome para pruebas web.

Conectá Chrome DevTools MCP opcional por proyecto. Abrí páginas, ejecutá escenarios en el navegador y conservá capturas y resultados junto a la sesión.

md

Instrucciones para tu proyecto.

Cargá AGENTS.md y skills. Generá una propuesta de AGENTS.md, revisala y editala antes de aplicarla explícitamente al proyecto.

{ }

17 herramientas para trabajar.

Leé, escribí, editá, buscá archivos, ejecutá comandos, consultá APIs y extraé páginas renderizadas. Llamadas, ejecución y resultados aparecen en vivo.

+

MCP, skills y promptings.

Agregá servidores MCP stdio o HTTP, habilitá skills y reutilizá prompts con variables. Configurá las extensiones desde la TUI.

85%

Continuidad en tareas largas.

Reabrí sesiones y continuá después de cancelar. La compactación automática cerca del 85% conserva el historial original y los efectos previos de las tools.

SQL

Claves y CLI para servidores.

Guardá las keys LLM en SQLite local sin llavero del escritorio. Usá el mismo agente por SSH o con --prompting desde scripts.

04 / FAQ

¿Dudas antes de empezar?

Instalación, modelos, credenciales y qué pasa con tu código.

¿Qué es S42 Agent?

Un agente de coding open source con una TUI estilo QBasic y una CLI sin interfaz. Trabaja en la carpeta de tu proyecto, usa el LLM que elijas y puede leer, editar y ejecutar herramientas con los permisos de tu usuario.

¿Es gratuito?

S42 Agent se distribuye con licencia MIT. El harness no tiene suscripción. Un proveedor LLM remoto puede cobrar por su API; los modelos locales usan tu propio hardware.

¿Necesito instalar Bun o Node?

El ejecutable compilado incluye Bun y funciona sin instalarlo aparte. Desarrollar desde fuente requiere Bun 1.4.2. Los comandos externos, servidores LLM y programas MCP se instalan por separado. Chrome DevTools MCP opcional requiere su propia instalación de Node y Chrome.

¿Qué modelos puedo usar?

llama.cpp es el proveedor por defecto. También admite DeepSeek y otros endpoints compatibles con Chat Completions. Configurá endpoint y clave en Models y elegí un ID real de modelo. Tools e imágenes dependen de las capacidades del modelo y de la configuración de su servidor.

¿Puedo usarlo en un servidor por SSH?

Sí. Abrí la TUI en una terminal ANSI o ejecutá el mismo agente con --prompting sin iniciar la interfaz. Las claves LLM se guardan en SQLite y no requieren D-Bus ni llavero del escritorio. Las funciones de navegador requieren su configuración externa.

¿Dónde se guardan las API keys?

En la tabla credentials de la base SQLite local del agente, sin cifrado adicional. Con configuración JSON legacy se usa config.json.credentials.sqlite junto al archivo. Las claves se separan por configuración, proveedor y endpoint. Los overrides CLI quedan en memoria; también se admiten variables de entorno. Las claves anteriores del llavero deben ingresarse una vez en Models.

¿Mi código permanece en mi computadora?

Los archivos y el historial se guardan localmente. El LLM elegido recibe el contexto que le envíes. Con un proveedor remoto, ese contexto sale de tu computadora; con un modelo local podés mantener local la inferencia. Los MCP y las herramientas configuradas también pueden acceder a servicios externos.

¿Cómo funcionan el plan, la verificación y Git?

TODO.md y Kanban conservan el progreso. Las verificaciones registran pruebas y evidencia reales. El panel Git muestra cambios e historial; commits y pushes siguen AGENTS.md y las instrucciones del proyecto activo. Generar AGENTS.md e inicializar un repositorio Git son acciones explícitas.

¿Puedo retomar una tarea larga o cancelada?

Sí. SQLite conserva sesiones, respuestas parciales y reasoning recibido. Reabrí la sesión para continuar. La compactación usa la ventana informada por el modelo y conserva el historial original; cancelar no deshace archivos modificados ni comandos ya ejecutados.

¿Qué plataformas hay y cómo actualizo?

La release incluye ejecutables para Linux glibc, macOS y Windows en x64 y ARM64. Linux x64 tiene smoke nativo del binario; los otros destinos son cross-builds. Para actualizar, cerrá el agente y ejecutá nuevamente el instalador de abajo. Se conservan configuración y sesiones.
